# ADR-0002: The Dictation state machine is sans-IO

**Status:** Accepted  
**Date:** 2026-10-11

## Context

The Swift predecessor's `DictationCoordinator` mixed decisions with I/O. It started the recorder, slept on cap timers and called the Transcriber, Inserter and notifier through protocol seams. A `cancelRequested` flag was shared between the Esc tap, the device-lost callback, the cap timer and the async finish path. Its tests needed fakes and real sleeps of 50 to 600 ms. One race was visible in the code: reloading the Model mid-Recording replaced the state, so the Hotkey-up was ignored and the Recording never stopped.

The fix is to move the decisions into a pure state machine that returns effects, run by a single thread with `now: Instant` passed in. This pattern, called sans-IO, is how [quinn-proto](https://github.com/quinn-rs/quinn) ("deterministic state machine ... no I/O internally"), str0m and [Firezone](https://www.firezone.dev/blog/sans-io) structure their protocol logic.

## Decision

`crates/core::Dictation` is a pure, synchronous state machine:

- `handle(event, now) -> Vec<Effect>` and `handle_timeout(now) -> Vec<Effect>`. The runner reports what happened (`HotkeyDown`, `EscPressed`, `RecordingStopped(recording)`, `Transcribed(transcript)`, ...) and executes the effects (`StartRecording`, `Transcribe(recording)`, `Insert(transcript)`, `Finished(outcome)`, ...).
- `poll_timeout() -> Option<Instant>` tells the runner when to call `handle_timeout`. Core never reads the clock.
- Model availability and Paused are separate from the Dictation phase. They only gate Hotkey-down, and never interrupt a Dictation in flight.
- Notification copy is derived from the outcome (`Outcome::notice`), so the policy stays in core and is tested there.

The runner lives in the app. It owns the OS seams (recorder, Esc tap, Transcriber, Inserter, notifications) and is the only caller of `Dictation`, from one thread.

## Consequences

- Every transition, including the 5-minute hard cap, is tested with plain function calls in microseconds and without fakes.
- One thread owns the state, so there are no shared flags and no races between callbacks.
- The CLI can drive the same machine headlessly (`AGENTS.md` §3).
- More types: `Event` and `Effect` enums plus a runner loop. That code is the price of the above.
- Presses during transcription are ignored, as in the Swift predecessor. Queuing them is the alternative; revisit if users hit it.
